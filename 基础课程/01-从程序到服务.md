本课目标：能解释“用户点一下按钮之后，为什么有好几个程序一起工作”。不需要先会编程。

## 1. 文件不是正在运行的程序

源码是程序员写下的规则。例如：“收到读文件请求时，先检查文件 ID，再返回文字。” `.go`、`.ts`、`.py` 是不同编程语言的源码文件。

运行中的程序叫**进程**。可以把源码理解为食谱，把进程理解为正在按食谱做饭的厨房。同一份食谱可以开多个厨房。

Go 源码通常先经过**编译**，生成 Windows 能执行的 `.exe`。编译器负责检查代码并生成可执行文件。编译成功只说明结构基本合法，不证明菜做得对，所以还需要测试。

Python 通常由 Python 运行环境读取源码。TypeScript 会先转成 JavaScript，再由 Node.js 或浏览器运行。这是三套运行方式，不是三种服务身份。

## 2. 什么叫服务

服务是一个持续等待请求、按约定返回结果的程序。SUMP 的 `files` 管文件，`memory` 管记忆，`reasoner` 组织模型推理。

**模块**是代码的组织单元；**服务**是运行时的角色。`protocol` 是共享协议库，它不会自己开一个服务窗口。`files` 则会启动独立进程。不能简单地把所有文件夹都叫正在运行的服务。

服务可以各自维护数据。例如记忆记录存在记忆服务自己的 SQLite 数据库里。SQLite 是嵌在程序里的数据库，通常把记录放在一个文件中，不需要另装一个数据库服务器。

## 3. 为什么要地址和端口

地址回答“哪台电脑”；端口回答“这台电脑里的哪个入口”。例如 `127.0.0.1:9501`：

- `127.0.0.1` 是“本机自己”。宿主机和虚拟机各有自己的本机，不能用这个地址互相访问。
- `9501` 是一个端口号。这里是 SUMP 前端的默认入口，不是网页版本号。
- `http://` 表示采用 HTTP 通信规则；`/api/chat` 这样的后半段表示具体功能入口。

虚拟机是宿主机中模拟出来的另一台电脑。两边都写 `127.0.0.1`，访问的仍分别是自己。跨机器要用对方在虚拟网络中的 IP 地址。

## 4. 请求和结果是什么

请求可以理解成一张工单：“请读取 ID 为 X 的文件”。结果是“找到了，内容为 Y”，或者“失败，原因是 Z”。

双方必须约定字段名、类型和意义，这套约定叫**协议**。下面只是教学示意，不是可以直接发给 SUMP 的完整报文：

```json
{"action":"read","input":{"id":"示例文件ID"}}
```

JSON 是用文字表示对象和列表的格式。大括号表示对象；键和值之间用冒号；字符串要用英文双引号。`id` 里的值是真实文件的编号，不是随便写一个文件路径。

SUMP 内部还会把消息编码为 MessagePack。它把相同的结构变成较紧凑的二进制。编码只改变运输形式，不自动增加权限或加密。

## 5. 为什么设置中心不是总指挥

设置中心保存“哪些服务在线、在哪里、提供什么”，并协助管理配置。它像通讯录。

服务从名册中找到地址后，直接访问对方。业务正文不必全部经过中心。这样文件服务忙的时候，不必让所有业务都堵在一个转发入口。

但中心故障、某个服务故障、业务错误仍需分别处理。独立服务不会自动消除所有竞态，也不会自动获得安全身份认证。

## 6. 模型、Reasoner 和工具分别是谁

**LLM** 是大语言模型，擅长理解和生成内容。它可以提出“调用某工具”的结构化要求，但真正执行的是程序。

**Reasoner** 是 SUMP 中组织这些步骤的服务：准备上下文、请求模型、分派工具、收集结果、决定何时交付。

**工具**是服务允许模型调用的某个动作。文件服务可以有多个动作，但并非每个动作都要开放给模型。看到函数存在，不等于模型能调用它。

## 7. 用一条流程串起来

```text
你在网页输入一句话
→ 前端服务接收
→ Reasoner 获取上下文并询问模型
→ 模型选择一个已开放工具
→ Reasoner 直接请求工具服务
→ 工具服务返回或稍后补报结果
→ Reasoner 继续推理并交付
→ 前端把回复显示出来
```

这是简化地图。实际字段和分支请读对应版本的流程说明，特别是暂停、审批、补报和失败情形。

## 你可以自测

1. 关闭浏览器，后台服务一定停止吗？不一定。网页与后台进程是两回事。
2. `files` 和 `protocol` 都是文件夹，它们都是独立服务吗？不是，后者是共享代码。
3. 测试返回“已受理”，能当作文件已经写完吗？不能。下一课会解释验证层次。
