# 术语词典：先读白话，再看正式名字

新增核心技术术语及相互关系见 [2026-10-26 版术语与知识地图](../核心技术/2026-10-26-149451db/10-术语与知识地图.md)。本页保留基础入门解释。

不要背这一页。遇到不懂的词，用编辑器查找功能搜索。每个条目先讲含义，再说明它在 SUMP 中的作用或容易误解之处。

同一个英文词在不同环境可能含义不同。例如模型 token 是计量单位，Bearer token 是认证凭据。

## 一、代码和运行环境

### 源码 / source code

**先这样理解：**人写的程序规则。

例如 main.go。它能阅读和修改；Windows 通常不能直接把 Go 源文件当作应用启动。先读入口和它调用的模块，不必从第一行读到最后一行。

### 编程语言 / Go、Python、TypeScript

**先这样理解：**写规则所用的语言。

Go 负责大部分后端服务；Python 在本项目主要用于 embedding；TypeScript 用于前端服务和网页。语言不同仍可通过同一消息协议协作。

### 编译 / build

**先这样理解：**把源码加工成可运行程序。

go build 生成可执行程序，也会发现类型或语法错误。它不检查所有业务行为，不能代替测试。

### 运行环境 / runtime

**先这样理解：**让某种程序能运行的一套工具。

Node.js 运行服务端 JavaScript；Python 解释器运行 Python。浏览器也能运行 JavaScript，但它与 Node.js 不在同一个环境。

### 进程 / process

**先这样理解：**一个正在运行的程序实例。

关闭浏览器不一定关闭前端服务器。独立进程有独立生命周期，崩溃后不会因为有网络重连逻辑就自动复活。

### 模块 / module 与包 / package

**先这样理解：**把相关代码放在一起的组织方式。

Go 的 go.mod 声明模块和依赖；一个模块里有多个包。protocol 是共享模块，files 是带可运行入口的模块。包名 server 不代表另一个独立进程。

### 依赖 / dependency 与 SDK

**先这样理解：**代码借用的库，以及针对某协议整理的一套开发工具。

MCP Go SDK 帮助处理 MCP 消息；SUMP 仍须自己处理映射、权限和结果归属。使用 SDK 不代表这些业务边界自动正确。

### Go Modules / go.mod / go.sum / go.work

**先这样理解：**Go 管理代码版本和本地模块的方式。

go.mod 列依赖要求；go.sum 校验下载内容；go.work 把多个本地模块组织成工作区。只复制一个目录可能丢失本地依赖，导致编译失败。

### Node / npm / React / Vite

**先这样理解：**前端开发中分工不同的组件。

Node 是服务端运行环境；npm 管依赖和脚本；React 组织页面组件及状态；Vite 构建网页资源。它们不是四个同义的“前端”。

### 虚拟环境 / venv

**先这样理解：**给一个 Python 项目单独存放依赖。

不同项目可以用不同库版本，减少相互影响。删掉 venv 不等于删业务数据，但重建前要确认路径。

### 工作目录 / 相对路径 / 绝对路径

**先这样理解：**程序寻找文件时的定位方式。

C:/完整目录/file.json 是绝对路径；../data/file.json 相对当前工作目录。相同命令换目录运行，可能读到不同配置。

### 环境变量 / PATH

**先这样理解：**进程启动时拿到的额外配置。

PATH 决定输入 go 时去哪里找程序。临时为一个窗口设置变量，不等于给整个 Windows 永久设置。密钥环境变量也可能被子进程继承。

### 构建产物 / artifact

**先这样理解：**构建或测试产生的文件。

例如 exe、前端 dist、测试日志。它们与源码不同，通常不全部放进 Git。阶段交付里只保留实际需要的文件。

### AST / 抽象语法树

**先这样理解：**把代码或命令按语法拆出的结构。

审批服务借它识别命令名称、参数及动态行为。它比简单搜关键词更能理解结构，但不等于已经预测所有运行效果。

## 二、网络与消息

### 客户端 / 服务端

**先这样理解：**一次交互中发起请求的一方与接收请求的一方。

同一个 MCP 服务可以对外接收请求，同时向另一个 MCP 服务发请求，所以可以同时有两种角色。

### IP / 端口 / URL

**先这样理解：**机器地址、进程入口编号和完整访问地址。

https://192.0.2.20:9903/mcp 包含协议、IP、端口和路径。192.0.2.20 是文档示例地址，不是可直接访问的服务地址，必须按实际环境替换。

### loopback / 回环 / localhost

**先这样理解：**指向当前机器自身的网络入口。

127.0.0.1 是常见回环 IPv4 地址。虚拟机里的 127.0.0.1 不是宿主机。0.0.0.0 是监听范围写法，不是客户端应访问的目标地址。

### 协议 / contract / 契约

**先这样理解：**双方约定的输入、输出及行为。

不仅包括字段类型，还包括“回执是否代表完成”“超时后能否重试”。JSON 解析成功不代表契约正确。

### HTTP / HTTPS

**先这样理解：**请求与响应的网络规则，以及加密保护版本。

HTTP 用于网页 API 和 MCP 入口。HTTPS 在 HTTP 外增加 TLS 保护；不等于自动给所有用户分配权限。

### WebSocket / WS

**先这样理解：**建立连接后双方都可以发送消息的通信方式。

SUMP 服务用它交换消息。协议支持长连接，不代表当前源码里的每次调用都复用同一连接。实际行为要看连接代码。

### SSE / Server-Sent Events

**先这样理解：**服务器通过 HTTP 持续向网页发送事件。

前端用它更新任务、对话和审批状态。它主要是服务器向浏览器推送，不是 WebSocket 的另一个名字。

### API / 动作 / endpoint

**先这样理解：**程序公开给别的程序使用的入口。

API 是一组调用约定；动作如 files.read；endpoint 是入口地址。不是每个 API 都面向模型或公网。

### JSON / MessagePack / 序列化

**先这样理解：**把结构化数据变成可传输的文字或字节。

JSON 方便人阅读；MessagePack 较紧凑。序列化是转换过程，反序列化是读回来；二进制不等于保密。

### JSON-RPC

**先这样理解：**在 JSON 消息里表达调用方法、参数、请求编号和结果。

MCP 使用它。id 用于对应请求与响应；method 指方法；params 放参数。SUMP 原生信封不是直接照搬这套格式。

### 信封 / Envelope

**先这样理解：**包住业务正文的路由外壳。

SUMP 信封包含类型、来源、目标、编号和追踪信息；正文叫 payload。理解时先看外壳往哪里走，再看业务参数。

### id / trace / boss / item_id

**先这样理解：**用途不同的标识。

id 关联一次请求响应；trace 追踪调用链；boss 表达业务回传归属；item_id 是异步受理句柄。不能互相替换，也不能只因 from 写了某服务名就认为身份已认证。

### 注册 / 名册 / 服务发现 / 心跳

**先这样理解：**让服务找到彼此并了解在线状态的机制。

注册是报到；名册记录地址与能力；服务发现是查询或接收这份信息；心跳是定期报平安。它们不意味着中心会转发全部业务。

### Schema / JSON Schema

**先这样理解：**规定一个数据对象应该怎么填写。

例如 ms 是整数且在范围内。MCP 绑定保存已审核的输入/输出规则，远端规则变化时停止调用，避免悄悄换契约。

### imports / exports / mapping

**先这样理解：**导入、对外发布、两边能力的对应表。

导入一个外部工具只给内部指定动作使用；exports 独立决定向外开放哪些原生工具。发现目录不等于授权全部工具。

### MCP / Stateless HTTP

**先这样理解：**模型上下文协议，以及当前选用的无会话请求方式。

MCP 标准化外部工具等能力的交互。Stateless 指不能依赖旧 HTTP 会话识别权限；服务仍可以保存受限观察记录，所以不等于完全无内存状态。

## 三、并发、错误和结果

### 同步 / 异步

**先这样理解：**是等待最终结果再答复，还是先回执再补报。

同步不代表整个系统只能做一个任务；异步也不代表任务必定执行成功。先返回 accepted 后仍可能失败。

### 并发 / 并行

**先这样理解：**多个工作在同一段时间推进，以及它们真正同时执行。

I/O 等待时多个调用可以并发。是否真正并行还取决于 CPU、目标服务和资源限制。增加并发不保证费用更低。

### goroutine / Context

**先这样理解：**Go 中的轻量并发执行单元，以及携带取消/超时等信息的对象。

启动 goroutine 后也需要管理生命周期。入站请求返回时 Context 可能被取消，所以异步工作不能盲目沿用它。

### 回执 / accepted / report_result

**先这样理解：**受理证明和随后送回的结果。

回执只说明服务接受了任务。report_result 可以带进度或终态；final 说的是报告是否结束，outcome_unknown 仍不代表远端确定停止。

### 竞态 / 早到报告 / 乱序

**先这样理解：**多个事件到达顺序与假设不一致。

例如最终结果比受理回执先到。M2 先预留记录并限制早到缓存，拿到句柄后精确匹配。随意 sleep 几秒不是可靠修复。

### 终态 / 去重 / 关联

**先这样理解：**确定结束的状态、忽略重复事件、确定归属。

一份最终结果不能因重复到达而交付两次；也不能把旧任务结果放进新任务。这要结合来源与多个标识判断。

### 超时 / 取消 / unknown

**先这样理解：**等待到限、主动停止等待，以及执行结果不确定。

网络断开后，远端可能已经做了操作。超时不能当作“没执行”，取消本地等待不能当作“远端已撤销”。

### 幂等 / 重试 / exactly-once

**先这样理解：**重复操作是否改变结果、再次发送、以及恰好执行一次的保证。

读取通常较易重试；转账或发送消息可能重复产生副作用。MCP 当前不承诺 exactly-once，也不自动重放结果未知的工具。

### 容量上限 / 背压 / 熔断

**先这样理解：**忙不过来时明确限制新工作的办法。

在途槽满就拒绝，避免内存和执行任务无限增长。它不是无限排队，也不是声称远端实际任务数量被完全控制。

### TTL / 临时观察记录 / resource URI

**先这样理解：**记录保留多久、保存状态的对象、以及读取它的地址。

MCP job 在内存中保留有限时间。TTL 到期或服务重启后无法恢复；sump://jobs/... 是 MCP 资源标识，不是网页地址。

### 业务错误 / 服务自身故障

**先这样理解：**操作本身失败，与承载它的服务出问题。

文件不存在是业务结果；配置损坏、监听失败是服务故障。主开发要求后者上报设置中心，不能把所有用户失败操作都记成服务崩溃。

## 四、模型、记忆和存储

### LLM / Agent / Reasoner

**先这样理解：**语言模型、能使用工具推进任务的系统、SUMP 的推理组织服务。

LLM 生成回答和工具请求；Agent 还包含状态、工具和执行回路；Reasoner 是此项目承担组织工作的服务名。

### 上下文 / token

**先这样理解：**模型本轮看到的资料，以及模型计量文本的单位。

token 不固定等于一个汉字或单词。上下文越长通常越贵，但压缩过度可能丢信息；需要明确保留什么。这里的 token 与认证 token 同名但不同义。

### embedding / 向量 / 余弦相似度

**先这样理解：**把文字转换成数字坐标，再比较接近程度。

相似度用于寻找相关记忆，不是判断事实真假。fake 后端只能用于接线测试，不能替代真实语义模型。

### bigram / 兜底

**先这样理解：**按相邻字符组合做较简单的文字匹配，以及主路径不可用时的替代办法。

它能在 embedding 不可用时维持部分搜索，但不会自动拥有相同语义理解能力。

### SQLite / 表 / 索引 / 事务

**先这样理解：**文件式数据库及组织、查找和成组写入机制。

表像有固定字段的记录本；索引帮助快速查找；事务让一组写入按约定一起成功或失败。程序使用数据库仍可能写错业务。

### 黑板 / task / conversation / hold

**先这样理解：**任务上下文容器、任务、会话、暂停控制。

同一会话可以产生多个任务；任务状态不等于聊天窗口状态。桌面新快照的暂停规则要与 MCP 结果归属修复一起理解。

### batch / Batchable / resident

**先这样理解：**批处理、允许被批处理的声明、常驻任务类型。

batch 让一次请求分派多项工作；只有目标明确允许才可调用。resident 与暂停行为有关，不要凭名字推断所有后台任务都能永远运行。

## 五、权限、证书和工程协作

### 认证 / 授权 / Bearer token

**先这样理解：**证明调用者持有凭据、决定能做什么、随请求提交的通行凭据。

持有共享 token 的人可能被视为同一主体。通过认证不等于有权调用所有工具；还需显式映射与执行端权限。

### TLS / CA / SAN / PEM / 私钥

**先这样理解：**加密通信、信任根、允许地址、证书文件格式和身份秘密。

客户端先验证证书链、地址和有效期，再通信。CA 证书可交给需要信任它的客户端；服务私钥必须保密。不要用跳过验证来掩盖地址错误。

### Origin / Host / 重定向 / 代理

**先这样理解：**网页来源、请求目标名称、服务器要求换地址、代转流量的程序。

MCP 入口限制 Host/Origin；外连不跟随重定向，也不默认套系统代理，以免固定目的地和凭据边界被改变。

### fail-closed / 最小权限

**先这样理解：**无法确认时拒绝，以及只开放当前必需能力。

审批不可用时不能偷偷执行。导入工具不自动成为对外工具。它们是具体默认行为，不能只写在文档口号里。

### Git / commit / branch / fork / PR

**先这样理解：**版本记录、一次保存、独立开发线、远程副本、请求合并。

修改文件不等于 commit；commit 不等于上传；push 才把提交发到远端；PR 请求主开发检查并合并。fork 是你账号下的仓库副本。

### 基线 / SHA / diff / merge / conflict

**先这样理解：**开发起点、提交指纹、差异、合并、无法自动拼接的冲突。

merge 完成只说明得到一份文件集合，仍需验证行为。目录名字叫 main 不代表一定等于 GitHub 当前 main。

### 单元测试 / 集成测试 / E2E / fixture

**先这样理解：**小范围行为检查、模块组合检查、完整链检查和受控测试对象。

fixture 可以是真实 HTTP 进程，但仍不是正式第三方产品。断言是“预期必须成立”的条件；没有断言的启动日志不能证明业务正确。

### CI / go vet / race / govulncheck

**先这样理解：**自动检查平台、静态问题检查、并发竞态检查和依赖漏洞检查。

这些各查不同问题。配置了 CI 不等于跑过；交叉编译出 Linux 程序不等于在 Linux 运行成功。

### VMware / Host-only / NAT / 桥接

**先这样理解：**虚拟机软件，以及不同网络连接方式。

Host-only 让宿主机和同网虚拟机互通；NAT 常用于虚拟机借宿主机上网；桥接使虚拟机接入外部局域网。首次实验选择 Host-only，公网仍是另一层部署任务。

### 许可证 / Apache / MIT

**先这样理解：**别人允许你如何使用与分发代码的条件。

开源不等于没有条件。项目和依赖可能使用不同许可证，分发时保留通知，不能仅凭库名字猜许可。

## 六、源码中还会看到的专名

### SUMP

这是项目名称。本知识库没有给它臆造英文全称。理解它的服务架构，比猜缩写更重要。

### ULID / UUID

都是生成唯一编号的方案，避免同时发生的请求撞号。ULID 通常带时间排序特性。编号能帮助关联，不自动证明是谁发送的请求，也不是访问密码。

### NapCat / OneBot 11

NapCat 是 QQ 接入所用的外部组件；OneBot 11 是消息事件和动作的接口约定。SUMP 的 qq 服务把这些消息转换成自己的任务输入。没有 NapCat 不妨碍独立网页门户，但 QQ 链无法因此自动工作。

### ONNX / ONNX Runtime

ONNX 是保存机器学习模型的一种格式；ONNX Runtime 是运行这类模型的软件。它们在 embedding 服务用于计算文本向量。模型文件、运行库和 tokenizer 必须配套，单独有一个文件名不代表可用。

### tokenizer / tokenizers / NumPy / msgspec / websockets

tokenizer 把文本切成模型认识的编号序列；tokenizers 是相关工具库。NumPy 处理数值数组；msgspec 帮 Python 编码和检查结构化消息；websockets 是 Python 的网络连接库。它们解决不同问题，不是另建五个业务服务。

### gorilla/websocket / modernc SQLite / excelize

这是 Go 依赖库的名字：分别帮助进行 WebSocket 通信、使用 SQLite 数据库、读写 Excel 文件。使用 excelize 不等于能任意处理所有 Office 格式；Word/PPT 需要看各自实现。

### base64 / ZIP / XML / TSV

base64 把二进制表示成可运输的文本，会变长，不是加密。ZIP 是压缩归档；docx、xlsx、pptx 内部也常用 ZIP 容纳 XML。XML 用标签表达文档结构。TSV 用制表符分隔表格列，方便把表格转成文本。

### POSIX / Bash / cmd / PowerShell

POSIX 是一组操作系统接口和行为约定；Bash、cmd、PowerShell 是不同命令解释器。相同文字在不同解释器里可能有不同意义。审批不能把 PowerShell 语法规则直接套给 Bash。

### REST / DOM / jsdom / Vitest / Markdown

REST 常用于描述围绕资源组织 HTTP API 的风格；DOM 是浏览器内的页面结构；jsdom 模拟这种结构供测试使用；Vitest 运行前端测试。Markdown 是轻量文字排版语法，本知识库的标题、列表和链接就是用它写的。

### UI / 组件 / 主题令牌 / CSS

UI 是用户看到并操作的界面。组件是可复用的界面块，例如一张审批卡片。CSS 决定布局和外观；主题令牌把颜色、间距等统一命名，便于整体调整。它们不决定后台是否批准命令。

### DSH / 云母 / 玻璃层

这些在前端历史说明中描述设计素材或视觉效果。桌面当前样式已使用自有令牌链，旧 README 的 DSH 导入说法与源码不一致。“云母”“玻璃”描述观感，不代表新增网络协议或权限机制。

### mutex / 锁 / atomic / 原子快照

锁控制多个执行分支何时能访问共享数据。atomic 帮某些读写作为不可拆开的操作完成。不可变规则快照意味着新调用读取一整份确定规则，不在处理一半时读到另一半新规则。它们是并发正确性的工具，不是越多越好。

### 缓存 / 派生数据 / cosine / priority

缓存保存可重新计算的内容，减少重复工作；派生数据从原始资料计算而来，例如记忆向量。cosine 是余弦相似度；priority 是优先级字段。缓存失效可重建，但原始业务记录丢失不能因此自动恢复。

### ACL / DHCP / SAN / PEM

ACL 是文件或资源的访问权限清单；在 Windows 中，Go 写文件时的 Unix 模式数值不能代替 Windows ACL 配置。DHCP 自动给网络设备分配 IP。SAN 是证书允许的地址，PEM 是证书和钥匙的文本封装格式；这些缩写在 VMware 实验中会遇到。

### Conformance / Inspector

Conformance 指协议符合性检查，验证实现是否满足协议规定。Inspector 是用于观察和调试 MCP 交互的工具。它们不是“装上就已通过”的认证；本知识库没有提供官方套件通过的证明。
