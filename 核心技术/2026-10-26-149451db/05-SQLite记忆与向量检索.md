## 1. 学习目标：先分清“保存”和“记得”

读完应能解释四件事：

- 聊天历史、正在执行的任务、长期记忆和模型上下文有什么区别。
- SQLite 用表、索引和事务解决什么问题。
- 向量为什么能帮助检索，却不能证明内容正确。
- 语义检索失败时，bigram 回退实际保留了什么能力。

把 memory 想成资料室。保存资料只是“放进柜子”；召回是“按当前问题挑出几页”；把挑出的资料交给模型，是第三件事。模型不会因为磁盘上有很多文件，就自动看到全部内容。

## 2. 四层资料各自放什么

| 层次 | 内容例子 | 生命周期和职责 |
|---|---|---|
| Reasoner 黑板 | 本轮消息、未返回工具、当前模型状态 | 内存中的工作记录，见上一课 |
| 会话与任务历史 | 用户说过什么、工具调用及结果属于哪个任务 | memory 保存原始轨迹与任务归属 |
| 长期条目 | “我喜欢简短说明”这类明确记忆 | 可被 `remember` 写入、`forget` 软删除 |
| 经验网 | 从完成过程提炼的做法、事实、偏好等 | 按相似性和关联组织，按需给模型线索 |

**模型上下文**是这一轮实际送进模型的消息集合。它通常只包含资料室的一部分；受条数和长度预算约束。

**预算**在这里指允许占用多少文本或条目，不一定指金钱。字符预算也不等于模型 token 预算：一个 token 不是固定一个汉字。

## 3. SQLite 是什么，为什么适合这个服务

SQLite 是嵌入式关系数据库。**嵌入式**表示程序可以通过库直接访问数据库文件，不必再运行一台独立的数据库服务器。

**关系数据库**把记录组织成有列名的表。例如 `tasks` 每行是一项任务，列里保存任务编号、会话编号、名字、状态和时间。

SUMP 的 memory 通过 Go 标准库 `database/sql` 使用 `modernc.org/sqlite` 驱动。**驱动**是让统一接口与具体数据库通信的适配库。

| 表 | 像哪一本记录册 | 重要字段 |
|---|---|---|
| `conversations` | 对话窗口目录 | id、title、entry、status |
| `tasks` | 工作任务目录 | id、conversation_id、name、status |
| `messages` | 消息流水 | conversation_id、task_id、role、content、seq |
| `memories` | 明确的长期条目 | kind、content、priority、status、embedding_model |

`messages.kind` 区分普通对话、推理和工具轨迹；`meta` 放额外结构化说明。界面能显示一条工具记录，不代表这条记录会原样再次输入模型。

源码入口：[store.Open 与表结构](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/store/store.go)、[长期记忆表](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/longterm/longterm.go)。

## 4. 主键、索引、约束，分别做什么

**主键**是表中一行的唯一身份，例如某个 task 的 id。它让别的记录能明确引用这一行。

**索引**像书后的检索目录，帮助按某些列查找。它需要额外空间和维护成本，不是加得越多越好。

**唯一约束**则是一条必须成立的规则。SUMP 用下面的部分唯一索引约束任务：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_tasks_one_active
ON tasks(conversation_id) WHERE status = 'active';
```

逐段读：`UNIQUE` 是不允许重复；`conversation_id` 是比较的列；`WHERE` 限定只对 active 行生效。所以同一会话可以有很多已完成任务，但最多一个 active 任务。

如果两个请求同时发现“没有当前任务”，只靠先查再写会发生竞争。这里数据库让一个创建成功，另一个遇到约束后回头读取已有任务。

源码入口：[EnsureTask 与 OpenTask](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/store/tasks.go)。

## 5. 事务、连接和顺序：别把它们当成一件事

**事务**是把一组数据库操作作为整体提交的机制。比如“写一份批次总单，再写它的所有子项”，不应只成功一半。下一课的 `batch.store.CreateJob` 就使用 `Begin → Commit`，失败时回滚。

但“用了 SQLite”不表示业务中的每组操作都已经放进事务。要在具体函数里找到事务开始、提交或回滚，才能作出这个判断。

memory 当前将连接池设为最多一个连接，并配置数据库锁等待时间。它降低同进程并发访问的复杂度，但不等于整个系统只有一个任务，也不证明无限吞吐能力。

**连接池**是数据库连接的管理器；**锁等待**是数据库暂时忙时等待的时间。它们与模型等待、工具超时不是同一个计时器。

消息的 `seq` 是逻辑顺序编号。网络发送可能先后错开，按 seq 读取可以恢复写入方表达的顺序；编号本身不证明跨服务操作具有事务一致性。

长期记忆与历史库共用数据库句柄，便于同进程访问；共用句柄并不会自动把两个函数的写操作合成一次事务。

## 6. 从历史到上下文：一次 recall 的工作

**recall** 可译为“召回”，就是按当前问题取资料。`memory.actionRecall` 大体进行以下步骤：

1. 确认会话的当前任务，缺少时创建；取得任务失败就停止这一轮。
2. 取这个任务的最近对话，按设置限制条数。
3. 去掉当前消息链已经带上的相同尾部，避免重复塞入。
4. 取 `priority > 0` 的核心长期条目，不要求它们与本次问题相似。
5. 在剩余条目中寻找相关记忆，并附上能取得的经验线头。
6. 把这些部分组装成 `【记忆】` 块，再通过 `resume` 交回 Reasoner。

**去重**是避免相同信息重复进入上下文；**核心条目**是优先级大于零的条目，不等于已经由外部事实核查证明真实。

现行 `compose.Inject` 把记忆块放在 **system 消息**中，通常在第一条 system 消息之后，替换此前同前缀的记忆块。这是在描述当前实现，不能据此声称记忆文本都值得信任。

如果外部恶意内容进入记忆，召回时可能再次影响模型。记忆来源、写入权限和注入边界属于后续防注入设计需要处理的问题，**本版没有在这里增加过滤机制**。

源码入口：[actionRecall](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/server/server.go)、[TrimOverlap、BuildMemory、Inject](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/compose/compose.go)。

## 7. 向量：用数字表示文字的某些特征

**embedding** 是把文字映射为一串数字的过程；得到的这串数字叫 **向量**。SUMP 让独立的 embedding 服务负责计算，memory 负责保存和检索。

举个教学例子，向量 `[1,0]` 和 `[0.9,0.1]` 方向很接近，`[0,1]` 与它们差得更多。真实模型通常有更多维度，不能把每个数字直接翻译成某一个汉字。

**维度**就是数字的个数。**余弦相似度**比较两串数字所指方向的接近程度；它用于排序相关程度，不是事实真实性概率。

当前相关记忆筛选阈值为 `0.45`。这是本版与所选模型相关的工程参数，不表示“有 45% 的概率是真的”，换模型后也不能直接照搬效果结论。

向量还需记录 `embedding_model`：不同模型即使维度相同，坐标含义也可能不同。原始文本是源数据，向量是可以重新计算的**派生数据**。

源码入口：[RankSemantic 与 cosine](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/longterm/rank.go)。

## 8. fake 与 ONNX：跑通接口和真实语义能力有区别

embedding 服务提供两类后端。**后端**在这里指具体用什么算法产生向量：

| 后端 | 实际做什么 | 能证明什么 |
|---|---|---|
| `fake` | 使用确定性的词片段特征哈希生成数字 | 用于接线、数据形状和稳定测试，不代表真实语义理解 |
| `onnx` | 载入本地模型，通过 ONNX Runtime 计算向量 | 可使用真实模型；质量仍需用具体样例评估 |

**哈希**是把输入映射成固定范围数值的办法；**确定性**表示相同输入在相同条件下给出相同结果。这里不是拿哈希值进行安全签名。

**ONNX** 是模型文件格式；**ONNX Runtime** 是运行这种模型的软件；**tokenizer** 把文字转换成模型输入编号。模型与 tokenizer 应配套。

当前 ONNX 后端选择 CPU 执行提供器，所以不能仅因电脑有显卡，就宣称该路径已使用 GPU 加速。

源码入口：[FakeBackend、OnnxBackend](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/embedding/sump_embedding/backends.py)。

## 9. bigram 回退究竟怎么工作

查询向量计算不可用时，`rankRelevant` 会回到本地字面匹配。对连续汉字，`Terms` 抽取相邻两个字；对字母、数字序列，主要按小写整词处理。

例如“明天喝咖啡”可产生“明天、天喝、喝咖、咖啡”。记录里出现越多查询片段，得分越高；同分再比较优先级和新旧，并受条数与字符预算限制。

这能找“咖啡”字样，却不能保证把“提神饮品”理解成咖啡。**回退**表示主路径失效时保留有限能力，不是效果完全等价。

还要区分两种失败：查询向量失败会转 bigram；条目向量补算部分失败时，当前代码继续用仍可参与的向量排序，并不整批转回字面检索。

源码会对缺失或模型标记不同的向量发起补算。但是旧模型补算失败且维度相同时，当前排序函数自身只核对维度，没有再核对模型标记；这一边界需要专项验证，不能概括成“模型切换已完全隔离”。

## 10. 运作模拟：找回饮食偏好

**这是教学模拟，不是准确率测量。** 假设库里已保存三个条目：A“喜欢咖啡”，B“平时用深色主题”，C“睡前不喝含咖啡因饮品”。

1. 用户询问“晚上适合喝什么”，Reasoner 把当前消息交给 memory。
2. 若 C 是核心记忆，它可直接进入核心部分；A、B 再参加相关性排序。
3. 真实 embedding 可能让与饮食相关的条目排得较前；是否达到阈值要看实际模型计算，不能凭文字保证。
4. 如果 embedding 不可用，字面回退可能找不到“咖啡”，于是相关部分更少，甚至为空。
5. memory 仍可以把最近对话和已有核心条目交回；模型应基于实际拿到的资料回答。

“没有召回某条”不等于数据库中没有那条，也可能是预算、阈值、模型、回退方式或状态过滤造成的。

## 11. 经验网与软删除，先抓住边界

**经验网**把条目与多个大类建立联系，用短的“线头”提示模型；需要细节时通过 `dig` 再取。**线头**是摘要和引用，不是把整库全部复制进模型。

Reasoner 的后台复盘可以提炼经验，但模型提炼可能错误。经验被记录下来不意味着它升级成已验证事实；使用时仍要保留来源意识。

`forget` 对长期条目执行**软删除**：改变状态，使正常召回不再选它。它不是安全擦除数据库文件；若需要彻底删除敏感数据，必须另外设计生命周期与备份处理。

源码入口：[经验提炼](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/reasoner/server/reflect.go)、[经验网算法](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/memnet/memnet.go)。

## 12. 从零复现：先读，再选是否运行

**纯阅读练习：**打开 `rank.go`，搜索 `Terms`、`Score`、`RankSemantic`。手写“明天喝咖啡”的四个片段，说明“字面相似”和“语义相似”为什么不同；再读 [TestTerms](https://github.com/NouSart/sump/blob/149451dbf9ec953006da7c1926c336cfd9da0633/memory/tests/longterm_test.go) 对照算法。

**可选运行：**先完成 [Windows 环境准备](../../基础课程/00-准备Windows开发环境.md)，用这版完整源码，在编辑器中打开 `memory` 目录的终端，执行：

```powershell
go test ./tests -run '^(TestTerms|TestEnsureTaskIsSingleton|TestRankSemanticThresholdBudgetAndOrder|TestInject)$' -count=1 -v
```

**预期：**四个用例各显示 PASS。任务和存储用例使用临时测试库；排序用例使用手工向量，不需要下载真实模型，不会证明真实语义效果。

`no tests to run` 应先检查版本和正则名称；依赖下载失败是环境问题；断言失败说明行为不符合该用例预期。不要为练习打开或修改日常助手的真实数据库。

本版每次检索可能读取多条记忆并逐一评分，并没有自动建立大型近似向量索引。条目增长后的检索成本需要测量；当前知识库没有把未来性能方案说成已实现。
